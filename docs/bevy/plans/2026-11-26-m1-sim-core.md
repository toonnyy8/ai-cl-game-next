# M1 Sim Core + Kenpachi + Ichigo (trace-replay gate) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `duel-sim` plays Kenpachi and Ichigo (all forms) with no CPU, and `duel-tools replay <trace>` re-runs every Kenpachi /
Ichigo trace of the answer key bit for bit.

**Architecture:**
- `duel-sim` is plain Rust (no Bevy, no globals): one `Match` value holds the whole sim (ECS-lite stores in spawn order, RNG, time,
  flow, gate, cinematic director, combat log). Snapshot = `clone()`, restore = assignment.
- Logic is ported by hand, file by file in `duel/MANIFEST` order; every Rust function names its Lisp source
  (`// port: duel/lisp/core-sim.lisp CORE-LATCH-STEP`). Data and knobs come from `duel-data`.
- The replayer does what `tools/port/oracle/replay.lisp` does: brains detached, the recorded vpads and sim RNG injected at each sim
  frame's pilot read, every step's combat log, `T`, `H` and the new raw-bits `B` line compared.
- Code not ported yet stops a replay with `UNPORTED <name>` (not a divergence), so every task has an exact check before the
  whole sim exists.

**Tech Stack:** Rust 1.99 (edition 2024), `libm` 0.2, serde / serde_json (through `duel-data` only); host ECL 24.5.10 and
Python 3 for Task 1 only.

**Spec:** `docs/bevy/BEVY_PORT.md` (§3 determinism, §4 crates, §5 port method and floats, §6 verification, §7 M1).
Also read: `docs/bevy/M0_NOTES.md` (§3 data files, §4 answer key and trace grammar, §6 open items), `docs/bevy/M0_CODE_FIELDS.md`
(the hooks to port by hand), `tools/port/oracle/trace.lisp` (header = the grammar, authoritative) and `replay.lisp`.

## Global Constraints

- **Freeze.** Lisp is frozen at tag `lisp-freeze` (395fd0b6). Never edit `duel/`, `engine/`, `tests/`. Task 1 edits
  `tools/port/oracle/` only (the recorder image, no `duel/` edit).
- **No redesign.** A Lisp bug is ported as a bug and listed in `docs/bevy/DIVERGENCES.md`. A drift is fixed in Rust, never in the key.
- **Crates** (spec §4): `duel-sim` depends on `duel-data` and `libm` only. No Bevy, no `static mut`, no thread-locals, no
  `unsafe` in `duel-sim`.
- **Floats** (spec §5.3): `f32` where Lisp has single-float, `f64` where double; a literal without `f0` is a double and
  promotes (CL contagion: f32 op f64 → f64, then the store's `(f32 …)` / slot type narrows); `sin cos atan2 hypot pow exp log
  sqrt` through `libm` (`sinf` … for f32); no FMA (`mul_add` is forbidden), no fast-math; CL `round` is banker's rounding; a
  fixnum counter that may pass `i32` is `i64`. Every CL-semantics helper lives in `duel-sim/src/cl.rs`.
- **PI.** The sim never reads a long-float `pi` value: sim constants `+pi+` / `+two-pi+` are the single-float defconstants,
  ported by hand.
- **Data, never retyped** (decision 5): move / kit / tuning values come from `duel_data::Data` (`Data::embedded()` /
  `Data::load(dir)`); knobs get typed accessors in `duel-sim/src/knobs.rs`; only the sim-side defconstants are hand-ported.
- **Brains** (decision 3): sim code that branches on `(brain e)` is ported faithfully behind `Fighter.has_brain: bool`. M1's
  replay keeps it `false`; M2 exercises `true`. A `has_brain` branch whose body is CPU code calls `unported!("…")`.
- **Determinism.** Entities iterate in spawn order (`engine/lisp/ecs.lisp` `do-entities`). The sim stream is drawn only inside
  the step. Look calls (vfx, sound, shake, captions, clips) are not ported in M1: leave `// look: <lisp call>` at the call
  site, unless a sim value reads their state (then port that state).
- **Hot path.** No heap allocation per step in the sim systems (the combat log line is the exception, and only while
  `Match.log_on`).
- **Scope of the gate** (decision 1): Hisagi and Yamamoto, the CPU (`cpu-*`, `core-ai`, `mcts`, `fq-online`, `strategy*`),
  PRACTICE, menus and every draw / look / HUD file are out (M2-M4). The 18 gate traces:
  `cvc-{kk,ki,ik,ii}-s{1,2,3}`, `cvctag-{ii,ik,kk}`, `trial-ki-ai-kenpachi`, `trial-ki-ai-ichigo`, `trial-sp-xch-r3`.
- **Answer key path.** `ORACLE` = `build/oracle` of the checkout that generated it (today
  `/media/8tsp/projects/ai-cl-game-next-bevy/build/oracle`); every command below takes it from `$ORACLE`.
- **Repo rules.** Bounded waits only; never `pkill -f` / `pgrep -f`. Subagents never push, merge or deploy, and never edit the
  DEVLOG or the manual. Never commit `build/`, `rs/target/`. Commit subjects start `Bevy port M1:`.

## Review Focus

1. **A step with no sim frame** (intro, cinematic, hitstop, slow-motion wait): the vpad clock must not advance and nothing is
   injected; a press buffered before it still fires after. Test `replay_skips_injection_without_sim_frame` (Task 6).
2. **Double contagion in a single-float formula** (`(* 0.5 x)` with `x` single): the product is f64 until stored. Tests
   `contagion_mul_half`, `round_half_even` (Task 2); the `B` line catches the rest per step.
3. **Entities added or removed during iteration** (a hazard spawning a hazard, a clone ending in its own step): Lisp's
   `do-entities` order and visibility rules must hold. Test `iteration_sees_spawn_order_and_late_spawns` (Task 4).
4. **A broken or foreign trace** (truncated file, a Hisagi trace, an unknown `E` action, the run ending before or after the
   trace): exit 1 / 3 with one line naming the step and item, never a panic. Tests `truncated_trace_is_an_error`,
   `unknown_event_is_an_error` (Task 6).
5. **Native vs wasm32**: the same replay must pass on `wasm32-wasip1`. Task 14 runs one trace there.

### Task 1: The raw-bits oracle line `B`

**Files:**
- Modify: `tools/port/oracle/trace.lisp`, `record.lisp`, `replay.lisp`, `gen.py`; `docs/bevy/oracle-index.json`; `docs/bevy/M0_NOTES.md` §4 (grammar row)

**Interfaces:**
- Produces: after each step's `H` line, one line `B <field> <field> …` (or `B =` when equal to the previous step's `B` text
  within the trace). Fields in this order, floats as 8 upper-case hex digits of the IEEE single bits (16 for a double),
  integers decimal, symbols as `prin1`:
  1. globals: `*timer*` `*hitstop*` `*slow-acc*` the 24 `*slowmo*` floats, `*flow*`, the cine frame (`-1` when no `*cine*`);
  2. per side (P1, P2): position x y z, yaw; `motion` vel x y z, kb x y z, kb-left, grounded (`T` / `NIL`); every
     `single-float` slot of `fighter` in slot order; the fixnum slots `sf hold stun freeze lock hoho-lock hoho-left guard-t
     gc-left guard-exit pre invuln armor-left land-sf combo-hits`; every `single-float` slot of `gauges` in slot order, then
     `reishi konpaku burn-step`;
  3. `|`, then per live hazard in entity order: `kind x y z px pz yaw speed size age life delay hits-left`.
  The slot lists are computed once at load from the `defcomponent` forms' `:type` (read `duel/lisp/components.lisp`), and the
  resolved names are written in the trace header as `# B fields: …` so Rust copies the order from there.
- Produces: `tr-f32-bits (x) -> integer`, built from `integer-decode-float` (no FFI); a NaN / infinity is an error.
- `tr-read` returns steps as `(:step log t-fields h-line b-line)`.

- [ ] **Step 1: Self-test for the bits.** In `trace.lisp`, add `tr-bits-selftest` asserting `1.0f0 → #x3F800000`,
  `-0.0f0 → #x80000000`, `0.1f0 → #x3DCCCCCD`, `least-positive-single-float → #x00000001`, `1.0d0 → #x3FF0000000000000`;
  `record.lisp` and `replay.lisp` call it at load and exit 2 on failure.
- [ ] **Step 2: `tr-b-line`** in `trace.lisp` (shared), emitted by `rec-step` after `H`, compared by `rp-step`
  (`rp-fail "B field <name>: want … got …"`, naming the first differing field through the header's field list).
- [ ] **Step 3: Verify on one trace.** `python3 tools/port/oracle/gen.py sim cvc-ki-s1 && python3 tools/port/oracle/gen.py replay cvc-ki-s1`
  (add the NAME filter to `sim` if it lacks one). Expected: `replay OK 21368 ticks`; the `H` lines are byte-identical to the
  old trace's (`grep '^H'` of both, `cmp`).
- [ ] **Step 4: Regenerate and re-pin.** `gen.py sim` (~9 min+), `gen.py replay` (63 OK), then regenerate
  `docs/bevy/oracle-index.json` (sha1s change; steps and last ticks must not). Record the key's new size in M0_NOTES §4.
- [ ] **Step 5: Commit** (`Bevy port M1: raw-bits B line in the answer key, re-pinned`).
