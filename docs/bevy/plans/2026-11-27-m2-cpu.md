# M2 The CPU (perception, core CPU, styles, strategies, MCTS, online learner) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Kenpachi's and Ichigo's CPUs run in `duel-sim`. `duel-tools replay --live <trace>` re-plays every Kenpachi / Ichigo
CvC trace of the answer key with both brains thinking for themselves, and matches it bit for bit. `duel-tools cvc` prints G2's
reference (`build/oracle/cvc-tag.txt`) byte for byte.

**Architecture:**
- The brain is a component on the fighter, so the cloned `Match` holds it. CPU state that Lisp keeps outside its snapshot roots lives
  in a separate `duel_sim::cpu::Search`, which a restore never touches. That state is the jobs, the stats, the fq tables and the
  page store. The game loop passes `(&mut Match, &mut Search)`.
- Logic is ported by hand in `duel/MANIFEST` order (`scripted` … `fq-online`). Every Rust function names its Lisp source. A strategy's
  `:FN` and a kit's `:ai` hooks resolve by name through one registry (`cpu::style::resolve`), like `kit::resolve`.
- The live replayer attaches brains as the frozen build does and injects nothing. On every step it compares `T` right after
  `brain-system`, plus the `C` CPU log lines (new in M2), the new CPU-state line `A`, and M1's `[` / `H` / `B` lines. The first `T` or
  `A` mismatch names the first CPU bug to the step.
- Until the MCTS ports, `--inject-plan` writes the recorded `*mc-plan*` and strategy picks from `A` at each step's end, so the core
  CPU, the styles and the strategy layer can be checked before the rollouts exist.

**Tech Stack:** Rust 1.99 (edition 2024), `libm` =0.2.16; host ECL 24.5.10 and Python 3 for Task 1 (the recorder) and the data
extractor only.

**Spec:** `docs/bevy/BEVY_PORT.md` (§3 determinism, §5 port method and floats, §6 verification, §7 the M2 row). Also read:
`docs/bevy/M1_NOTES.md` (§3 stubbed mode, §5 numbers, §7 brain branches, §10 the M2 carries and deferred minors),
`docs/bevy/M0_NOTES.md` §4 (the trace grammar; `tools/port/oracle/trace.lisp`'s header is authoritative),
`engine/lisp/snapshot.lisp` and `duel/lisp/sim-state.lisp` (what a Lisp snapshot restores).

## Global Constraints

- **Freeze.** Lisp is frozen at tag `lisp-freeze` (395fd0b6). Never edit `duel/`, `engine/`, `tests/`. Task 1 edits
  `tools/port/oracle/` only. Data goes through `tools/port/extract/`.
- **No redesign.** A Lisp bug is ported as a bug and listed in `docs/bevy/DIVERGENCES.md`. A drift is fixed in Rust, never in the key.
- **Crates:** `duel-sim` depends on `duel-data` and `libm` only. No Bevy, no clock, no `static mut`, no thread-locals, no `unsafe`.
  The `mcfull` / `stratlayer` stats lines' milliseconds come from a caller-supplied `Search.clock: fn() -> u64` (default: always 0).
  Those two lines are never compared.
- **Floats** (M1's rules, unchanged): a bare literal is single-float; double only from `d0`, `pi`, `(float x 1d0)`, double data;
  CL contagion; `exp` / `log` / `sqrt` through `libm` (`cpu-mcts.lisp:179`'s `exp` included); no `mul_add`; CL `round` is banker's,
  `floor` rounds toward −∞ (`(floor (* 12 (sim-rnd01)))`, `(round (* 1000 v))`). Every helper lives in `cl.rs`.
- **Data, never retyped:** CPU knobs (`*cai-*`, `*ai-*`, `*mc-*`, `*strat-*`, `*fq-*`, the outcome tables `*mc-outcomes*` /
  `*mc-outcomes-hard*`, the styles' own `defparameter`s) come from `duel-data`. A value the extractor lacks is added to
  `tools/port/extract/extract.lisp`, re-extracted, and the checksum re-pinned (M1: `3ddcd77c9a34edf5`). Check that each `Params`
  f32 key holding an integer token is read as an integer (M1 minor T3).
- **Snapshot boundary = Lisp's.** Everything `sim-snapshot` reaches from its roots (the ECS stores with the BRAIN component,
  `*mc-plan*`, `*mc-next*`, the roots in `sim-state.lisp`) is in `Match`. Everything else the CPU writes at runtime is in `Search`:
  `*mc-jobs*`, `*strat-jobs*`, `*mc-full-stats*`, `*strat-stats*`, `*strat-picks*`, `*fq-tables*`, the page. Lisp depends on this
  split: job scores survive `sim-restore live`, `strat-full-step` writes `brain-strat` after the restore, and a stand-in brain added
  inside a rollout vanishes with the restore. No `HashMap` / `HashSet` iteration anywhere in CPU state (Lisp restores hash tables
  in their saved order). Use plists as `Vec` with GETF's first-match rule.
- **RNG.** The sim stream is drawn only inside the step and the rollouts. A rollout reseeds through `SimRng::set_state` (its 0 → 1
  rule); `SimRng.state` becomes private (M1 minor T2).
- **Hot path.** 0 heap allocations per battle step with both CPUs on. That includes the per-step snapshot while jobs exist: one
  preallocated snapshot slot per job, restored with `clone_from` (M1 §5's clone allocations).
- **`unported!`** stays replay-only. M2's game loop and rollouts check `m.unported` themselves (Task 8, Task 10).
- **Scope:** Kenpachi's and Ichigo's CPUs. Out of scope:
  - Hisagi's and Yamamoto's CPUs (`cpu-hisagi-*`, `cpu-ih-*`, `cpu-hk-*`, `hs-tick-brain`; M4): their style names resolve to
    `unported!`.
  - The masher (`masher.lisp`, debug 81030+; M5): `masher-apply!` ports as a no-op unless that debug seat is set, which is
    `unported!`.
  - The fq page persistence in the browser (M3): `Search.page` is an in-memory map with Lisp's `page-get` / `page-set` semantics.
- **The gate traces** (15 live): `cvc-{kk,ki,ik,ii}-s{1,2,3}`, `cvctag-{ii,ik,kk}`, plus Task 1's vs-human traces
  `vs-learn` and `vs-cpu`. The M1 brainless gate (22 traces) stays green after every task.
- **Answer key path.** `ORACLE` = `/media/8tsp/projects/ai-cl-game-next-bevy/build/oracle`; every command takes it from `$ORACLE`.
- **Repo rules.** Bounded waits only; never `pkill -f` / `pgrep -f`. Subagents never push, merge or deploy, and never edit the
  DEVLOG or the manual. Never commit `build/`, `rs/target/`. Commit subjects start `Bevy port M2:`. Ignore hook lines that say
  CONTEXT WARNING: they report the parent session.

## Review Focus

1. **A rollout's restore keeps what Lisp keeps.** A job's two scores survive the restore. `brain-strat` written after the restore
   stays. The stand-in brain for a human goes. The live RNG is back. Test `rollout_leaves_live_state_and_keeps_search`
   (Task 8; a port of `tools/simgate/fulltest.lisp`): one extra rollout per job, then `Match` must equal the copy taken before and
   `Search` must hold the new score.
2. **A cinematic, a pause or the match's end while jobs are pending** (`sim-snapshot-ok-p` false): jobs are dropped and the plan
   cleared. A rollout that reaches a K.O. stops without `go-results`. Tests `jobs_dropped_when_snapshot_not_ok` and
   `rollout_never_ends_the_match` (Task 8).
3. **A human side** (no brain): perception reads the human, the rollout adds a stand-in brain with `cam_relative` false, and
   VIEW-STEP runs for a `cam_relative` pilot. Task 1 records `vs-cpu`, Task 9 replays it, and test `stand_in_brain_for_human`
   (Task 8) covers the rollout part.
4. **GETF and plist order in strategies** (a duplicated key, `:BASE` missing, a rule naming no output, NIL as "the CPU's own value"):
   test `strat_value_first_match_and_nil` (Task 5), with values taken from `tests/duel-rules/strategy.lisp` and hand-built plists.
5. **Floor and round on negative or tie values in the CPU's integer maths** (`(floor (* n (sim-rnd01)))` at the top of the range,
   `(round (* 1000 v))` at ±x.5, `(floor d step)` with a negative distance): tests `cpu_floor_round_edges` (Task 4) and
   `plan_score_rounding` (Task 8).
