# hud-font — the Lisp HUD's baked text

`atlas.r8` (one R8 texture, 1024 wide, rows of single-channel signed-distance cells) and `metrics.bin` (header, per-face ascent /
descent, then one 9-word record per glyph) are generated by `tools/sdf-bake.py` and committed. `lhud-font.c` `#embed`s both into the
wasm's static data (C23 `#embed`, accepted by emcc's clang); nothing is read or consed at load. Format and design:
`docs/duel/DUEL_LISP_HUD.md` §4.2 and §8.

The baked glyphs are a Modified Version (outlines turned into distance fields); each face's OFL.txt travels in `duel/`. No font file
is tracked.

## What is baked

Body tier (32 px em, 4 px spread) and display tier (96 px em), by `(face, tier)`:

- ASCII 32-126 in the display, mono and sans faces (body tier);
- the strings of `(kj ...)` (Mincho body), `(bigkj ...)` (Mincho display), `(big ...)` (display face, display tier) and `(zh ...)` (sans;
  a character it lacks, e.g. the 闘 of 決闘, goes to the Mincho; the non-CJK symbols also to the Latin faces) forms in
  `duel/lisp/lhud-*.lisp`, chiefly `lhud-charset.lisp`, `lhud-data.lisp` and `lhud-menu-data.lisp`: the only source since the HTML UI
  left (2026-11-11, DUEL_LISP_HUD §16; before, the bake also scanned `hud.js` / `menu.js`);
- `(lhud-shape ...)` characters are baked nowhere: the HUD draws them as polygons.
- `SHAPES` in `tools/sdf-bake.py`: SVG paths baked as glyphs at private-use codes, body tier only (the soul flame, U+E000 in the
  sans: DUEL_LISP_HUD §14).

`tests/duel-rules/lhud-charset.lisp` (part of the duel-rules host test) fails, naming the character, when the bake lacks one: a tag
form's at its face and tier, or any non-ASCII character of a string the HUD can show that no tag names (every string literal of
`lhud-*.lisp`, `webhud.lisp` and `webui.lisp` read by the Lisp reader, docstrings left out; every kit's form name, U tag, intro line and
move callout). Such a string needs a tag form (or an entry in `lhud-charset.lisp`).

## Rebake

```sh
uv venv build/sdf-venv && uv pip install --python build/sdf-venv/bin/python fonttools skia-pathops numpy   # once
build/sdf-venv/bin/python -I tools/sdf-bake.py --fetch   # downloads the faces and OFL.txt into build/font-cache/ (git-ignored), once
build/sdf-venv/bin/python -I tools/sdf-bake.py           # writes atlas.r8, metrics.bin and ../FONT-LICENSE-*.txt
```

The bake is deterministic: two runs give byte-identical files. Then run the host tests and `./build.sh duel`.
